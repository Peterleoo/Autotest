# 轻量功能规格说明书：非专业人员团队自测工作台 (Team Self-Test Console)

> **文档标识**：spec-team-self-test-console  
> **所属版本**：v1.0 (Now 首期核心交付)  
> **面向对象**：非专业测试人员（业务开发、PM、业务功能测试、运营）  
> **遵循规范**：ProductOS Lightweight Spec · 业务规则契约 · 零和原则

---

## 一、 目标用户与核心问题 (Context & Problem)

* **目标用户**：没有自动化代码编写经验的业务开发工程师、产品经理（PM）以及业务功能测试人员。
* **核心阻力与代价**：
  * 过去依赖命令行（CLI）执行测试与排错，非专业人员不会配置 Python 依赖，看到终端堆栈报错无从下手；
  * 执行过程处于“黑盒不可见”状态，不知道手机当前停留在哪个页面，缺乏安全感；
  * 自测成果无法沉淀为可复现的团队资产，每次迭代只能反复手工点点点，费时费力且容易遗漏低级回归缺陷。
* **预期价值**：
  * 提供零代码、开箱即用的浏览器端控制台；
  * 支持输入自然语言意图即刻发起真机自测，配合同步投屏监控，自测成功一键固化入库，并可由团队或 CI 流水线一键秒级免 Token 回归。

---

## 二、 非目标与理由 (Non-Goals with Rationale - 核心防线)

| 序号 | 坚决不做的非目标 (Non-Goal) | 排除理由与战略依据 |
| :---: | :--- | :--- |
| 1 | **暂不提供 iOS 真机驱动支持** | iOS 真机环境依赖苹果证书签名、WebDriverAgent 重编与开发者账号配置，部署运维门槛高，会极度拖慢非专业人员上手体验。首期 100% 聚焦 Android 平台真机即插即用与模拟器。 |
| 2 | **暂不做复杂的多机并行分布式调度** | 团队自测核心诉求是“交互即时性”与“看投屏确认结果”。首期采用单任务队列排队模式，即可满足小团队日常自测频次，避免过早陷入分布式中间件与网络状态机的泥潭。 |
| 3 | **暂不支持无代码/低代码流程图拖拽编排** | 拖拽流维护成本高且极易损坏。核心资产必须保持为后台自动固化生成的标准 Pytest Python 脚本，以保持与研发代码库的天然亲和力。 |
| 4 | **不越界输出后端微服务架构或数据库物理 DDL** | 恪守产品经理职责：只定义实体状态机、交互规则、接口业务契约与非功能需求，系统实现细节由技术团队裁决。 |

## 三、 用户体验与核心功能机制 (User Flow & Requirements)

### 3.1 核心自测三步主路径 (The 3-Step Happy Path)
1. **第一步：环境感知与意图输入**
   - 用户打开浏览器控制台，系统自动显示当前已连接的 Android 设备状态（型号、分辨率、电量、在线状态）；
   - 用户在多行文本框中输入自然语言自测意图（支持快捷选择历史常用模版，如“安装最新包并登录测试账号”）。
2. **第二步：实时投屏与步骤执行观察**
   - 用户点击【开始 AI 自测】；
   - 界面左侧展示**实时手机投屏镜像**（延迟 < 500ms），右侧以**流式时间线**展示当前 AI 解析出的动作（点击、输入、滑动、验证）；
   - 执行到哪一步，投屏界面自动用半透明矩形高亮标出当前操作的控件区域，时间线对应步骤点亮并打上毫秒级耗时。
3. **第三步：结果审查与一键固化**
   - 测试通过后，界面弹出“🎉 自测通过”总结卡片，展示全流程截图合辑与接口校验结果；
   - 用户点击【一键固化为团队用例】，输入用例标题（如“登录异常流回归”）并归入所属业务模块；
   - 固化成功后，该用例进入【团队用例库】，后续可一键触发秒级复测，或接入 CI 流水线自动执行。

## 四、 核心实体与业务契约 (Entities & Contracts)

### 4.1 核心实体生命周期

```text
[新建自测会话 (Session)]
       │ 用户输入意图并点击执行
       ▼
[执行中 (Running)] ──── 发生业务阻断 / 断言失败 ──► [失败终止 (Failed)] (提供人话诊断与现场截图)
       │ 全流程步骤执行成功 & 断言匹配
       ▼
[自测成功 (Passed)]
       │ 用户点击“一键固化”
       ▼
[已固化入库 (Solidified)] ──► 自动生成 tests/solidified/test_*.py
       │
       ▼ 可重复触发
[确定性秒级回归 (Regression Run)] ──► 0 Token 消耗 · 标准 Allure 报告
```

### 4.2 业务规则与异常边界处理 (Business Rules & Edge Cases)
1. **设备离线与占用处理**：
   - 若检测无可用设备，【开始自测】按钮置灰，并给出明确的人话指引：“未检测到连接的 Android 设备，请确保 USB 调试已开启或启动模拟器”；
   - 若设备正在执行其他成员任务，系统提示“设备繁忙（由成员张三使用中），已加入排队队列，当前排在第 1 位”。
2. **AI 执行超时与卡顿阻断**：
   - 单步骤 AI 决策超时上限为 20 秒；超过上限触发兜底重试，最多重试 2 次；
   - 若连续遇到系统权限弹窗（如“允许访问相册”），AI 意图驱动引擎优先自动点击“仅在使用中允许”类常规放行选项，并在时间线中记录“已自动放行系统权限弹窗”。
3. **通俗化错误诊断（人话转换规则）**：
   - 严禁向非专业人员抛出 `ElementNotFoundException` 或 Python Traceback；
   - 错误必须统一转译为三段式人话文案：**“在第 X 步[动作名称]失败：未能识别到‘登录’按钮。可能原因：当前停留在引导页或网络未加载完成。建议检查应用状态后重试。”**

## 五、 验收用例与完成准则 (Acceptance Criteria & DoD)

* **AC-01 (环境零门槛)**：非专业测试人员仅需通过浏览器访问本地/内网 Web 页面，无需安装 Python、Appium 或配置环境变量即可正常操作；
* **AC-02 (投屏与时间线实时性)**：点击开始后，投屏界面延迟 ≤ 500ms，时间线在 AI 执行每个动作时 1 秒内完成状态刷新并呈现高亮操作框；
* **AC-03 (一键固化有效性)**：自测成功后点击“一键固化”，系统必须在 `tests/solidified/` 下正确落盘标准 Python Pytest 脚本，且脚本无需大模型介入在 30 秒内复测通过；
* **AC-04 (团队用例库查阅与回放)**：团队用例库列表中可查阅历史固化用例的详细步骤、截图与最近回归状态，支持点击“立即回放”完成秒级复核；
* **AC-05 (CI/CD 触发接口)**：提供标准 HTTP Webhook，向该端点发送 POST 请求可自动触发指定模块已固化用例的全量回归。

## 六、 待验证假设与后续关注 (Assumptions & Next Steps)

* **核心待验证假设**：非专业人员在使用自然语言意图描述复杂业务场景时，其提示词表述习惯是否具备足够的语义稳定性？
* **最小验证手段**：选取 2 位业务开发与 1 位业务 PM，使用自测工作台在真实 Android 演示包上执行 3 个典型场景（登录、个人中心修改、商品加购），记录首次意图成功率与修改轮次。
