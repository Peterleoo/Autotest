## 一、 战略转向背景与核心价值主张

### 1.1 关键洞察（从单步自测走向系统级业务编排）
- **非专业人员的真实使用门槛**：本产品根本目标客群是**非专业测试人员（业务功能测试、前端/全栈开发、产品经理、运营）**。对于该群体而言，纯 CLI 命令行 + 本地跑 Python/Pytest 的“极客模式”存在巨大认知断层。
- **从“单句盲测”到“需求文档驱动与自由编排”**：单纯输入一句话容易产生测试盲区；而非专业测试人员手头往往有现成的需求文档（PRD/Word/PDF）。通过大模型智能提取并结合 Generative UI 让人原地微调编排，在保持真机现场上下文（`keep_state: true`）下连续探索，构筑了真正的系统级自测闭环。
- **三级火箭分层感知破解高成本高延迟**：单步 5~10 秒的视觉全量大图调用在大规模测试中不可接受，通过原生 UIAutomator 控件树纯文本毫秒级短路，单步提速 80%，彻底扫平规模化推广障碍。

```mermaid
flowchart LR
    A[需求文档上传 / 自然语言意图] --> B[Suite Builder: 智能提取与 Generative UI 编排]
    B --> C[分层感知三级火箭调度 + 原生真机执行]
    C --> D[可视化审查执行步骤与断言结果]
    D --> E[一键固化存盘至团队用例库]
    E --> F[CI/CD 流水线 / 团队一键全量秒级 0 Token 回归]
```

### 1.2 核心价值主张 (Value Proposition)
1. **零代码、零环境配置自测**：非专业人员通过浏览器 Web 控制台输入一段业务话术或上传 PRD 文档，即可自动驱动移动端设备完成全链路操作；
2. **看得见的实时执行反馈**：控制台提供真机低延迟投屏与步骤执行标注，界面点到哪、断言验什么一目了然；
3. **团队资产即时沉淀**：自测成功后“一键固化”，系统自动在后台生成标准 Pytest 脚本并沉淀为团队共享用例，彻底告别写代码与维护定位器的噩梦；
4. **低边际成本与发版防护**：固化后的用例支持一键批量回归与 CI/CD 触发，0 Token 成本、秒级执行，为非专业团队筑牢防线。

1. **多设备矩阵并发调度与兼容性自测**：
   - 支持单套用例套件同时下发至多台不同品牌/屏幕分辨率的物理真机（小米、vivo、OPPO、华为等），并行收集各设备执行状态与截屏差异；
2. **跨平台设备生态拓展（iOS 真机轻量化接入）**：
   - 探索基于标准化 WebDriver 代理的 iOS 真机轻量免越狱调试链路，拓展自测设备矩阵；
3. **探索性无剧本 AI 巡检（Exploratory Monkey）**：
   - 在业务闲时自动探索未覆盖的边缘路径与异常弱网边界，自动沉淀异常日志与崩溃复现场景。

## 三、 产品实体生命周期与关键业务规则

### 3.1 核心业务实体状态机

```mermaid
stateDiagram-v2
    [*] --> 编写自测意图: 浏览器打开控制台
    编写自测意图 --> 执行中_实时投屏: 点击开始自测
    执行中_实时投屏 --> 自测未通过: 业务报错 / 断言失败 / 超时
    自测未通过 --> 调整意图或应用: 查阅截图与通俗人话诊断
    执行中_实时投屏 --> 自测成功: 步骤完整执行 & 断言成功
    自测成功 --> 一键固化中: 点击“固化为团队用例”
    一键固化中 --> 团队用例库_活跃: 生成标准 Pytest 脚本并归档
    团队用例库_活跃 --> CI全量回归: 界面发起回归 / CI Webhook
    CI全量回归 --> 回归通过: 零 Token 极速校验
    CI全量回归 --> 回归报警: 界面红标提示阻塞发版
```

### 3.2 关键业务契约与非功能需求 (NFR)
1. **极简操作交互体验 (UX)**：
   - 核心自测流程必须在 **3 步内闭环**：选择设备 ➔ 输入意图 ➔ 点击执行；
   - 错误提示必须转化为“产品/业务人话”（例如：“未在当前界面找到‘确定’按钮，当前处于登录页”，严禁直接暴露 `NoSuchElementException` 堆栈）。
2. **实时画面流畅性**：
   - Web 控制台真机投屏延迟控制在 500ms 以内，帧率 ≥ 15fps，满足非专业人员实时观察执行的要求。
3. **零成本与高确定性**：
   - 固化用例在回归执行时严格脱离大模型，0 Token 开销，单步响应耗时 ≤ 1.5s。
